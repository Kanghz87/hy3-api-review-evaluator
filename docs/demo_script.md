# Two-minute demo script

目标：在 120 秒内展示一次真实 Hy3 审查和质量评估，不显示 API Key。

## 录制前准备

1. 完成 `.env` 配置，并确认页面侧栏只显示“Hy3 API Key: 已配置”。
2. 可为 Demo 临时设置 `HY3_REASONING_EFFORT=low`；模型仍是实际 `hy3`，只是减少等待。
3. 先运行一次 smoke，确认 TokenHub 可访问、预算账本有余额、响应可以解析。
4. 启动应用：

   ```powershell
   .venv\Scripts\streamlit.exe run app.py
   ```

5. 准备文件 `datasets/specs/hard-15-mixed-security.yaml`。
6. 浏览器缩放到 80%～90%，关闭通知和包含 Key 的终端窗口。
7. 录制范围只选浏览器页面，不录 `.env`、TokenHub 控制台或 PowerShell 历史。

## 时间轴和台词

### 0～12 秒：问题与定位

画面停在页面标题和非官方声明。

台词：

> 这是 Hy3 API Review Evaluator。它解决两个问题：OpenAPI 人工审查容易遗漏，而大模型
> 报告又可能错误定位或编造证据。本项目既生成审查，也评价审查是否可信。

### 12～28 秒：上传和选择重点

- 审查重点选择“安全性”。
- 上传 `hard-15-mixed-security.yaml`。

台词：

> 我上传一份合成的 OpenAPI 3.1 文档。文件只作为数据解析，远程引用不会下载，文档中的
> 指令不会执行。

### 28～43 秒：确定性检查

滚动到确定性检查表，指出 HTTP、DELETE 鉴权、路径参数和错误响应。

台词：

> 调用模型前，本地代码已经给出可复现证据。这些 finding 之后会成为模型不能绕过的事实
> 锚点。

### 43～76 秒：真实 Hy3

点击“运行 Hy3 审查并评估报告”。等待时保持 spinner 可见。

台词：

> 现在第一次调用 Hy3 生成严格 JSON 审查，第二次让 Hy3 按六维 Rubric 评价报告。每次调用
> 都先检查 token 预算，整个实验最多 85 万 token。

如果等待超过 33 秒，可在后期只加速等待区间，不删除错误或结果画面，也不要把缓存结果说成
刚刚调用。

### 76～100 秒：评分与证据

- 展示总分、结论和六维表格。
- 展开一个 finding，展示 JSON Pointer、quote 和绿色“匹配”。

台词：

> 评分关注事实、定位、严重程度、证据、建议和幻觉。这里的 pointer 和 quote 会回到原文
> 逐项核验；即使 judge 打高分，不存在的接口仍会被本地门禁强制判零。

### 100～113 秒：下载与复现

点击 JSON 或 CSV 下载按钮，但不打开本机敏感目录。

台词：

> 结果可以下载为 JSON 或防公式注入的 CSV。仓库还包含 20 个场景、60 条报告、评测脚本和
> 人工盲标页面。

### 113～120 秒：结束声明

滚回顶部非官方声明。

台词：

> 这是腾讯犀牛鸟计划个人实战作品，并非腾讯官方软件。

## 录制后检查

- 总时长不超过 2 分钟。
- 画面和音频中没有 Key、Authorization Header、`.env` 内容或 TokenHub 余额。
- 确实展示 `model=hy3` 的运行结果或脱敏验证记录。
- 没有把 preliminary 指标说成人工一致性结论。
- 视频说明附仓库链接、运行命令、许可证和非官方声明。
