## 已修复问题

1. **引用与报告证据脱敏**：文档级脱敏器沿局部引用传播敏感字段上下文，识别常见
   `X-API-Key`、认证方案声明的自定义头，以及组件中的敏感命名示例；通过访问状态去重处理
   引用环，不下载引用。已识别的敏感值也用于清理 reviewer 的本地发现、judge 请求中的
   报告、页面文字和 JSON / CSV 导出。原始上传文档保持不变。
2. **JSON 完整性**：移除对序列化 JSON 的第二次破坏性替换；文本模式不吞掉引号或已脱敏
   占位符。`api_key=`、`access_token=`、`client_secret=` 均有实际回归测试。
3. **去重与召回**：同位置、同标题但具体问题不同的本地发现保留独立 ID；仅删除实质相同的
   发现。评估按标题及具体原因匹配同位置锚点，缺少两项中的一项不再获得满召回分。
4. **请求前容量检查**：超过 100 条本地发现或本地发现文本超出上下文限制时，先要求拆分输入，
   不发起模型调用。提示词告知剩余 finding 容量；模型仍超出容量时安全拒绝，不静默删项。
5. **judge 一致性**：严重失败标志与原因列表矛盾、或原因只有空白时，作为结构错误拒绝接受。
   模拟的矛盾满分响应不再返回“通过”。
6. **输入规范化及错误隔离**：拒绝重复 JSON / YAML 字段（含规范化后的键冲突）、非 JSON
   标量和非有限数字；YAML 日期与时间戳保留原字符串，整数响应键规范化为字符串。
   超过 500 字符的文档位置及超长标题在加载时给出安全输入错误；本地规则输出超限也统一
   转为安全错误，页面不直接暴露校验异常。

证据校验在一次评分中复用已脱敏文档，避免每条证据重复脱敏全文。
CSV 的文档级脱敏需要传入 `build_csv_export(report, evaluation, spec=loaded_spec)`；
应用已使用这一调用方式。保留的两参数兼容接口只有字符串模式脱敏，无法自行推断源文档凭据。

## 限制与交接

### 2026-09-14 补充修复：脱敏结构与证据缺失

同一尚未提交的 0.2.1 补丁继续修复两项边界问题：

- 短敏感值（如 `all`、`pass`、`low`）不再改写报告中的固定枚举。页面、JSON / CSV
  和模型请求共享类型感知的脱敏逻辑；正文继续脱敏，包含敏感值的 finding ID 使用一致的
  不透明替代 ID，替换后过长的文本按字段限制截断。原始报告保持不变，不用脱敏副本重新评分。
- 脱敏后已消失的子位置不再被序列化为 `null` 并充当匹配证据。原文真正存在的 `null`
  仍可匹配；预览只显示脱敏占位符，不泄露被遮盖的值。

补充检查实际重跑原始 60 条报告：逐条 CSV 与补丁前完全相同，20/20 严格排序，6/6
报告级对抗检出，12/12 补充边界检查通过；人工标注文件哈希未变。新增回归覆盖短敏感值、
合法导出、原始对象不变、页面渲染、judge 请求字段关联，以及真实 null / 伪造 null 的区分。
上述检查均为离线执行，没有新增 Hy3 调用，也不构成修复版新的线上验证。

补充修复后完整 pytest 为 **151 项通过**（本轮新增 28 项），Ruff 检查、格式检查、

### 提交前补充检查：异常下标与 CSV 证据完整性

最后补充两项小范围修复：证据位置中的非 ASCII 数字、前导零、超长数组下标和非法
波浪号转义均安全判为未找到，不抛出整数转换异常；模型提供的证据位置与文档位置一样
限制为 500 字符。合法字典键（如 `01`、Unicode 键或正确转义的波浪号）仍然支持。

通过 `id` 和 `evidence_index` 关联；保留原有 finding、coverage、dimension、summary 行。
新增证据行同样经过敏感内容脱敏和 CSV 公式防护。
