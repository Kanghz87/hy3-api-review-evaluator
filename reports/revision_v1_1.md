## 修复范围

| 问题 | 修订及验证 |
| --- | --- |
| 正常文档的空报告被机械判低分 | 增加 `review_coverage` 与无问题专用分支；缺证据、遗漏本地问题、上下文截断不能通过；本地最多有条件通过 |
| 敏感 Schema 示例失去字段上下文 | 脱敏传递敏感字段名和 password 格式上下文，覆盖 example/default/examples/enum/const；原类型定义保留 |
| `$ref` 定位指向引用壳而非定义 | 参数引用、引用链和 Path Item 引用保留实际定义的 JSON Pointer；操作计数跟随局部 Path Item 引用 |
| 同类同位置的不同问题互相覆盖 | 同一位置保存多个事实锚点；有歧义时不任意认领；重复一条发现不能抵消遗漏另一条 |
| 否定建议或引用的恶意文本被误判为建议执行 | 危险动作检查针对作者建议，识别直接否定和转折分句；肯定危险建议仍触发失败 |
| 可选认证漏检 | 识别 `security: [{}]` 及带匿名分支的认证备选列表 |
| 合法 required / allOf 被认定为高危无效契约 | 区分开放 Schema 未约束字段与 closed Schema 禁止必填字段；不在组合 Schema 上凭同层 properties 作错误推断 |
| 深层 YAML 在检查前递归崩溃 | 构造期间限制深度和节点，解析递归错误转为安全输入错误；仍拒绝 aliases |
| 模型投影静默省略部分节点或补出不存在的节点 | 保留实际传入的文档分支，脱敏并按整体字符上限截断，不凭空生成顶层节点 |
| 原始评测集缺少正常边界样本 | 增加独立声明预期结果的 12 份补充文档，含 4 份无预期本地问题的文档；人工字段均为 null |

页面可展示无问题报告的范围引用，JSON / CSV 导出保留范围和总分。初始化预算账本的错误纳入
页面安全错误处理。原始生成器在当前版本拒绝覆盖冻结数据；新在线脚本按版本隔离输出并拒绝
混入旧版评分记录。

规则依据：[OpenAPI 3.1 Security Requirement](https://spec.openapis.org/oas/v3.1.0.html#security-requirement-object)
允许空对象表示匿名备选；[JSON Schema required](https://json-schema.org/draft/2020-12/json-schema-validation#section-6.5.3)
约束属性存在，不要求所有必填属性都必须出现在同层 `properties`。

### 跨版本变化没有隐藏

6 条报告的本地分数发生变化，其余 54 条不变：

| 记录 | v1.0 | v1.1 |
| --- | ---: | ---: |
| easy-06-undefined-required-property-good | 100.00 | 90.00 |
| easy-06-undefined-required-property-medium | 80.00 | 75.00 |
| medium-09-undefined-security-scheme-good | 81.25 | 100.00 |
| medium-09-undefined-security-scheme-medium | 65.00 | 83.75 |
| hard-16-schema-compatibility-good | 100.00 | 90.00 |
| hard-16-schema-compatibility-medium | 83.75 | 78.75 |

Schema 场景旧报告沿用了高风险判断；修复后，开放 Schema 的未约束必填字段不再被当作必然
无效，旧报告的严重程度分因此下降。认证场景上升来自同位置多个事实锚点的正确匹配。
这是规则语义修正，不是根据人工分数调参。

以旧版 33 条真实人工分数作**跨版本描述性对照**，新版本地 Spearman 为 0.9108、
MAE 为 5.8333；旧版本地为 0.9143、5.5303。相关性略降、误差略增，如实保留；这既不能
说成新版人工验证，也不能据此断言修复后的实际判定能力变差。人工标注使用旧版设定，且
共享合成场景。旧版混合指标 0.9480 / 4.1667 不应拿来当作新版混合成绩。

## 工程验证与剩余边界

- `ruff check` 和格式检查通过；96 项自动化测试通过，包括两个保存结果的 Streamlit 渲染测试。
- 原始数据集校验、历史模型结果校验、33 条人工对照的来源指纹和指标复算均通过。
- 在 Windows / Python 3.12 上实际构建 0.2.0 的 wheel 和 sdist，并在新建虚拟环境中安装 wheel；
  依赖一致性、包内 Rubric、CLI、主应用与标注页面加载、历史数据及人工指标校验全部通过。
  该安装检查没有调用 Hy3，完成后已清理专用临时验证环境，原开发环境不变。
- 首次沙箱运行的临时目录权限错误、首次无隔离构建缺少 hatchling 均保留为工程排查事实；
  使用正常本机权限和声明的隔离构建依赖后通过。新修订尚未推送，因此不声称远程 CI 已验证新版。
- 提交前密钥扫描包含本地真实 Key 精确匹配检查；扫描不输出 Key 值。
- 本次不重新收集 33 条人工标注，不创建新仓库，不发布活动材料，不自动推送公开仓库。

本地规则仍不是完整 OpenAPI / JSON Schema 验证器；组合 Schema 的某些错误需要专用验证器
或语义复核。文本否定检测与脱敏是有限启发式，不能保证处理所有自然语言和未知凭据格式。
空报告范围证据说明“检查了哪些输入”，不是证明不存在业务逻辑漏洞。

原始 good 报告部分由本地规则辅助构造，存在构造与评分耦合；新增样本是在发现缺陷后构造的
回归集，也不是独立盲测。完整新版研究验证仍需另行规划版本匹配的人工/模型重复实验，不能
用本次两条真实调用或模拟 judge 单元测试替代。录 Demo 时以当前实际耗时与分数为准，可明确
加速等待区间，但不把读取缓存说成新调用。
